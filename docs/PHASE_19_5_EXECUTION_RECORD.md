## Defects found and dispositions

1. **Inventory generator latent breakage (Phase 19 residue).**
   `generate-localization-inventory.mjs` could not evaluate the composed
   `englishMessages` (Phase 19 spread composition) — fixed by extracting the
   unexported `baseEnglishMessagesInternal` literal and recomposing the
   surface; the marker now accepts module-private `const` declarations. The
   frozen Phase 19 inventory file was not regenerated (still the `c807082d`
   snapshot by design).
2. **Throwaway checker bugs.** The `.claude/tmp` slice checker referenced an
   out-of-scope variable for the identical-value allowlist, mishandled the
   basename dot in full-key matching, and wrongly banned 完成/成功 (valid
   Japanese; the ban existed to catch Chinese leakage). All fixed. The over-
   broad ban caused a handful of agents to reword natural 完成 phrasings
   (できあがる/完了 variants) — harmless draft variance flagged for the native
   reviewer.
3. **Scenario-2 math-contract deviation.** The ja agent emitted
   `{mathFallback}` reasoning objects for four math templates (es/pt ship
   plain-string reasoning there) and hardcoded instance numbers (8/40/20%/28%,
   30/84/36%/20%) in two of them. Converted to plain strings that mirror the
   es placeholder/literal policy per template; the full es-vs-ja placeholder
   parity audit across all 81 templates × every field reports **0
   deviations**.
4. **Language self-name convention.** The base-1-core agent first translated
   `language.es419`/`language.ptBr` into Japanese glosses; restored glosses
   (`スペイン語（ラテンアメリカ）`/`ポルトガル語（ブラジル）`) to match the
   es/pt cross-gloss convention after the sync allowlist analysis; `language.ja`
   added to every catalog (typed `displayNameKey` parity) — an intentional
   shared, additive change.
5. **`table.insight.points` kept Latin "pt"** — fixed to `{{value}}点`
   (matching the es/pt translation of the same key); quality-gate regex also
   corrected to allow required full-width ？！ punctuation while still banning
   full-width alphanumerics.

## Bundle impact of unreleased draft catalogs (review remediation #11)

Measured with `expo export --platform ios` (Hermes bytecode, single main
bundle) against the remediated tree:

| Build | Bundle bytes | Japanese kana code units |
| --- | --- | --- |
| production profile | 7,327,758 | **4** (none — the draft catalog is absent) |
| internal-preview profile | 7,327,757 | **4** (none — catalogs load as async chunks on demand) |

Before the remediation, the statically imported ja catalog contributed
~429 KB of raw TS (~363 KB of string content, ≈75,000 kana code units) to
every bundle. After converting the three draft locales (es-419, pt-BR, ja —
~1.1 MB raw combined) to lazy `import()` chunks behind the locale profile:

- production bundles exclude the draft catalogs entirely (Metro
  dead-code-eliminates the loader: `EXPO_PUBLIC_RM_LOCALE_PROFILE` inlines to
  `"production"`, the provider's draft guard folds to `false`, and the
  dynamic-import chain is unreachable);
- internal-preview bundles keep the dynamic-import chain but do not eagerly
  include the chunk bytes (Metro emits the draft modules for on-demand
  fetching when the profile selects them);
- development builds behave like internal-preview.

The measured kana counts (4) are stray matches from released-locale strings,
not draft content. Bundle bytes differ by 1 byte between profiles, confirming
the draft payload is not statically present in either.

Note: because Metro inlines `EXPO_PUBLIC_*` only in the literal
`process.env.EXPO_PUBLIC_*` form, `internalPreview.ts` must keep that exact
spelling (an optional-chained or aliased read defeats inlining and would put
the drafts back into production bundles — guarded by
`src/localization/draftReachability.test.ts`).

## Round 2 - remediation review fixes (2026-09-04)

A post-remediation review identified 4 P1 and 7 P2 defects in the first remediation pass, plus 1 P3. All are now fixed:

1. **[P1] Profile plugin ran after expo-localization** - replaced with a dynamic `app.config.js` that computes the locale profile and rewrites the expo-localization plugin options BEFORE plugin resolution. Verified with a REAL prebuild integration test.
2. **[P1] Draft catalog loading did not propagate through context** - `draftCatalogVersion` is now a dependency of every catalog-reading callback and the memoized context value. Proven by the isolated `LocalizationProvider.lazyLoad.test.tsx` suite.
3. **[P1] Coach release flag exposed all drafts together** - replaced the boolean with a per-language allowlist (`RM_RELEASED_COACH_LANGUAGES=ja`). Tests prove releasing ja leaves es-419/pt-BR rejected.
4. **[P1] Inventory --commit provenance was false** - the generator now requires HEAD to match the supplied commit and the tracked tree to be clean when --commit is used. The ja inventory was regenerated with ambient-HEAD provenance, honestly labeled `sourceFreezeCommitSource: "HEAD"`.
5. **[P2] Draft catalogs were in the production bundle** - replaced runtime dynamic imports with a build-time module graph. Production exports measured: ja catalog content absent (0 kana units vs ~72,000 before).
6. **[P2] Failed loads cached permanently** - loadWaiters cleared in `finally`.
7. **[P2] Global test setup masked the loader** - draft registration moved to a catalog-only fixture.
8. **[P2] Parity comparison was conditional** - now unconditional against the reviewed es-419 policy baseline for every field and every variant.
9. **[P2] Variant test was a no-op** - fixed the choice.id indexing bug.
10. **[P2] CLI validation after fs mutation** - moved before tmpRoot setup.
11. **[P2] Inventory tests mutated a tracked file** - now restore exact original bytes.
12. **[P3] Sample prose drift** - prose must now contain each mapped value outside the map block (enforced by test).
